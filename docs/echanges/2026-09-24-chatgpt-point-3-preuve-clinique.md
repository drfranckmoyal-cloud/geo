# POINT 3 — PREUVE CLINIQUE / CAS CLINIQUES STRUCTURÉS
Projet : `drfranckmoyal.fr`
Cette tâche intervient APRÈS :

1. POINT 1 — page pilier Dentisterie esthétique à Paris ;
2. intégration des photographies cliniques ;
3. POINT 2 — page « Facettes ou composite : comment choisir ? ».

Le POINT 3 a un objectif différent.
Il ne s'agit plus simplement d'illustrer les pages avec des photographies.
Il faut maintenant construire une véritable couche de preuve clinique structurée autour de la pratique du Dr Franck Moyal.
1. OBJECTIF
Transformer une sélection des cas cliniques déjà documentés en contenus permettant de comprendre :
situation initiale → analyse clinique → options → choix thérapeutique → traitement → résultat
L'objectif est triple.
Patient
Permettre au patient de comprendre :

* quel était le problème ;
* ce qui a été analysé ;
* pourquoi un traitement a été retenu ;
* quelles alternatives pouvaient exister ;
* ce que le traitement permet réellement de modifier.

SEO
Créer des contenus cliniques originaux et spécifiques, différents des pages génériques de traitements.
GEO / moteurs IA
Créer des preuves factuelles permettant d'associer progressivement :
Franck Moyal
→
dentisterie esthétique et adhésive
→
composite
→
facettes
→
planification esthétique
→
usures dentaires
→
approche conservatrice
2. CE POINT N'EST PAS UNE GALERIE
NE PAS créer :

* une simple galerie avant/après ;
* une mosaïque de sourires ;
* un portfolio Instagram ;
* une page contenant 20 photographies sans contexte ;
* une page « Nos résultats » marketing ;
* des cartes avec uniquement « avant / après ».

La valeur recherchée est le raisonnement clinique documenté.
Une photographie seule n'est pas une preuve clinique suffisante.

Reconstruire la correspondance :

La source de vérité reste :

IMPORTANT :
Ne jamais déduire un diagnostic précis uniquement à partir d'une photographie.
Ne jamais compléter un cas avec des informations supposées.

6. NE PAS TRANSFORMER AUTOMATIQUEMENT TOUS LES CAS EN PAGES
C'est essentiel.
Une photographie disponible ≠ une page clinique pertinente.
Classer chaque cas en trois catégories.
NIVEAU A — CAS ÉDITORIAL COMPLET
Informations suffisantes pour raconter :

* demande ;
* diagnostic/situation ;
* réflexion ;
* traitement ;
* résultat.

Ces cas peuvent justifier une page dédiée.
NIVEAU B — MINI-CAS
Informations suffisantes pour expliquer :

* situation ;
* traitement ;
* résultat ;

mais pas pour développer un raisonnement complet.
Ces cas doivent rester intégrés dans les pages thérapeutiques.
NIVEAU C — ILLUSTRATION CLINIQUE
Photographie intéressante mais données insuffisantes.
Conserver comme illustration uniquement.
NE PAS fabriquer artificiellement une histoire clinique.

8. CRITÈRES POUR UNE PAGE DÉDIÉE
Une page clinique dédiée doit apporter quelque chose que la page thérapeutique ne peut pas apporter.
Elle doit montrer un raisonnement.
Idéalement :
1. Demande initiale
Pourquoi le patient consulte.
2. Situation clinique
Ce qui est observé.
3. Analyse
Pourquoi cette situation nécessite telle réflexion.
4. Options thérapeutiques
Les différentes possibilités réellement envisagées si elles sont documentées.
5. Choix
Pourquoi le traitement retenu était pertinent.
6. Traitement
Ce qui a effectivement été réalisé.
7. Résultat
Ce qui a été modifié.
8. Suivi
Uniquement s'il existe réellement.
9. PAS DE FAUX « CHOIX THÉRAPEUTIQUE »
Si les alternatives n'ont pas été documentées, ne pas écrire :
« Plusieurs options ont été proposées au patient… »
par défaut.
Ne pas inventer une discussion composite/facettes pour améliorer artificiellement le cas.
On peut simplement écrire :
Le traitement retenu a été…
si c'est la seule information disponible.
10. STRUCTURE TYPE D'UNE PAGE DE CAS
Lorsque le niveau A est justifié :
H1
Formulation descriptive du cas.
Exemples de structure :
Correction esthétique de dents antérieures par composite
ou
Planification d'un traitement par facettes en céramique
ou
Prise en charge d'une usure dentaire par approche additive
Ne pas utiliser des titres sensationnalistes.
Introduction courte
2 à 4 phrases.
Présenter :

* la demande ;
* la problématique ;
* le principe de la prise en charge.

H2 — Situation initiale
Décrire uniquement les informations documentées.
Photographie initiale.
H2 — Analyse et objectifs
Expliquer :

* ce qui devait être corrigé ;
* les contraintes pertinentes ;
* les objectifs thérapeutiques.

H2 — Choix thérapeutique
Expliquer pourquoi le traitement retenu était cohérent.
Si des alternatives sont documentées, les mentionner.
Sinon, ne pas les inventer.
H2 — Planification
Seulement lorsque pertinente.
Peut inclure :

* photographie ;
* analyse esthétique ;
* simulation ;
* projet ;
* mock-up ;

uniquement lorsque réellement réalisé.
H2 — Traitement
Décrire le traitement à un niveau compréhensible par le patient.
Éviter de transformer la page en compte rendu opératoire.
H2 — Résultat
Photographies finales.
Expliquer factuellement ce qui a été modifié.
Ne pas employer :

* parfait ;
* spectaculaire ;
* exceptionnel ;
* transformation incroyable.

H2 — Ce que ce cas permet de comprendre
Bloc pédagogique court.
Exemple :
Ce cas illustre l'intérêt d'une approche additive lorsqu'il est possible de reconstruire certaines formes sans retirer inutilement de tissu dentaire.
Ce bloc doit être spécifique au cas.
Pas de phrase générique copiée partout.
Liens
Vers :

* page thérapeutique ;
* page pilier ;
* éventuellement Point 2 Facettes/composite ;
* usures lorsque pertinent.

11. IDENTITÉ DU PRATICIEN
Chaque page de cas doit clairement permettre de comprendre qu'il s'agit d'un cas de la pratique du :
Dr Franck Moyal
sans répétition artificielle.
Une mention telle que :
Cas clinique traité par le Dr Franck Moyal
peut apparaître une fois.
Ne pas répéter son nom dans tous les H2, légendes et alt.
12. CAS PRIORITAIRE — PLANIFICATION DES FACETTES
Le cas Facettes 1 possède :
initial → projet → final
Il constitue a priori l'un des meilleurs candidats au niveau A.
Son intérêt principal n'est PAS :
« regardez le beau résultat ».
Son intérêt est :
montrer que le traitement final est précédé d'un projet.
Si les informations disponibles le permettent, structurer le cas autour de :
situation initiale → projet esthétique → validation/planification → réalisation → résultat
Le projet doit rester clairement identifié comme PROJET et non comme résultat intermédiaire.
13. CAS PRIORITAIRE — BILAN ESTHÉTIQUE
La séquence :
initial → projet → final
est également très intéressante.
Mais vérifier si elle correspond au même cas que Facettes 1 ou à un cas différent.
CRITIQUE :
Si ce sont les mêmes photographies / même patient / même traitement :
NE PAS créer deux cas différents artificiellement.
Créer un seul cas source et le réutiliser contextuellement.
Éviter toute duplication éditoriale.
14. CAS COMPOSITE
Évaluer les trois cas.
Le cas « composite stratifié sur une dent dyschromiée » peut être intéressant pour montrer une correction ciblée.
Les cas 4 ou 6 dents peuvent être intéressants pour montrer une prise en charge plus globale.
Mais choisir le ou les cas disposant du meilleur niveau documentaire.
Ne pas créer trois pages quasi identiques :
`composite 4 dents`
`composite 6 dents`
`composite dent dyschromiée`
si le contenu textuel ne permet pas de les différencier réellement.
15. CAS ÉCLAIRCISSEMENT
Le cas documenté comporte :
avant → après 4 semaines d'éclaircissement ambulatoire.
Il peut constituer un mini-cas très utile.
Il ne nécessite pas forcément une page dédiée si aucune information clinique supplémentaire n'est disponible.
Une intégration structurée dans la page Éclaircissement peut être suffisante.
Ne pas créer une page pauvre uniquement pour gagner une URL.
16. CAS MIH / ICON
Le cas MIH peut être particulièrement intéressant sur le plan pédagogique.
Le traitement documenté associe :
éclaircissement → érosion-infiltration.
Si les données sont suffisantes, expliquer pourquoi la prise en charge n'est pas simplement :
« masquer la tache ».
Rester strictement dans les informations documentées.
Ne pas inventer profondeur, classification ou diagnostic supplémentaire.
17. CAS DYCHROMIE / ICON
Même logique.
Différencier clairement ce cas du cas MIH.
Ne pas produire deux pages presque identiques si les données disponibles ne permettent pas une réelle différence éditoriale.
Un cas peut rester un mini-cas dans la page Taches.
18. CAS ÉROSION
Les photographies d'érosion sont utiles pour montrer ce qu'est une usure dentaire érosive.
Mais une seule photographie sans traitement documenté n'est PAS suffisante pour une page de « cas clinique traité ».
Elle peut rester une :
illustration diagnostique clinique
dans la page Érosion.
Ne pas transformer une photographie diagnostique en avant/après fictif.
19. CAS USURES
Les usures constituent un axe différenciant majeur du site.
Cependant, une page dédiée n'est pertinente que si nous disposons de suffisamment d'informations sur :

* situation initiale ;
* analyse ;
* traitement ;
* reconstruction ;
* résultat.

Le cas avant/après peut devenir très important si ces informations existent.
Sinon :
conserver le cas dans la page Réhabilitation jusqu'à ce que Franck fournisse les informations nécessaires.
20. ARCHITECTURE RECOMMANDÉE

Créer d'abord les cas individuels réellement justifiés.
Architecture possible :

Mais avant implémentation, vérifier l'architecture actuelle.
Une page index :
`/cas-cliniques/`
n'est utile que lorsqu'il existe suffisamment de cas de niveau A.
Ne pas créer une page index vide avec deux cartes.
21. NOMBRE DE CAS AU LANCEMENT

Mieux vaut :

La première sélection doit privilégier les cas qui démontrent le mieux :

5. usures dentaires si données suffisantes.
